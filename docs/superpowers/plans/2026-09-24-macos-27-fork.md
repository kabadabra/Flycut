# Flycut macOS 27 Fork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and run a distinct, credited Flycut fork on macOS 27 and prepare a maintainable release path.

**Architecture:** Retain the existing Objective-C/AppKit application. Fix macOS target configuration, clipboard state handling, and login registration in place. Keep indexing and graph output local; make the public fork instructions reproducible.

**Tech Stack:** Objective-C, AppKit, ServiceManagement, Xcode 27, QMD, Graphify, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-24-macos-27-fork-design.md`

## Global Constraints

- macOS app deployment minimum: 12.0.
- Keep the name Flycut and preserve the MIT license and original attribution.
- Fork bundle identifier: `com.edynamics.flycut` (the earlier preview used `com.kabadabra.flycut`).
- Direct download release first; CloudKit and App Store distribution are excluded until provisioned for the fork.
- Do not erase existing clipboard contents at launch.

## Review Focus

- Existing clipboard text at launch remains intact.
- Rapid successive copies enter history in the right order without stale attribution.
- Flycut's own paste does not immediately enter history again.
- Denied pasteboard or Accessibility permission has understandable recovery instructions.
- Startup registration reflects actual OS status after relaunch.
